First release of **ruckcode** (`rc`): an ACP-native agentic coding agent in Rust, organised around development-lifecycle modes instead of permission modes.

## Highlights

- **Lifecycle modes.** Modes like explore, design, implement, test, review and release live in `.ruckcode/modes.toml`. Each mode sets its prompt, allowed tools, mise tasks, MCP tools, permissions, hooks and model/profile. `rc init` generates the six lifecycle modes (or `--minimal` plan/build/verify) from your repo's real mise tasks. Shift+Tab cycles modes, and the agent can propose a switch with `SwitchMode` for you to approve.
- **mise tasks as tools.** Each mode exposes only the tasks it selects, as `mise__<task>` tools. When a mode selects many tasks, they collapse into `MiseListTasks` / `MiseRun` lookup tools to keep context small.
- **Hooks.** Seven events: session start, prompt submit, pre/post tool use, post-edit, mode change and stop. Post-edit hooks run your formatter or linter once per turn on the edited files and can feed failures back as an automatic fix turn.
- **ACP-native.** The agent speaks only the Agent Client Protocol. It uses the official `agent-client-protocol` SDK for transport and `agent-client-protocol-schema` types. The `rc` TUI and headless mode are ACP clients, and `rc acp` serves the agent over stdio for editors such as Zed. Supported methods: session list/load/resume/close, model config option, usage and notice updates, plus `_ruckcode/*` extensions.
- **AskUserQuestion.** Structured single- and multi-select questions with free-text "Other", shown as a TUI picker. Editors without the extension fall back to permission prompts.
- **MCP servers.** stdio and streamable-HTTP servers from `config.toml`, a Claude Code-style `.mcp.json`, or the editor via ACP. Their tools are exposed as `mcp__<server>__<tool>` and selected per mode with `mcp_tools`. `rc mcp list` shows their status.
- **Traceable transcripts.** Every session is an append-only `.ruckcode/sessions/<id>.jsonl` that you commit with your code. It records full prompts and replies (including reasoning), every tool call's input, output, diff, permission decision and duration, hook runs, mode changes and per-request timing and token metrics. Resume with `rc -c`, `rc -r [ID]` or `rc sessions`.

## Providers and setup

- Anthropic (streaming, tool use, prompt caching, extended thinking) and any OpenAI-compatible endpoint (OpenAI, Ollama, OpenRouter, vLLM, LM Studio), including reasoning output.
- `rc setup` is a TUI onboarding wizard that runs automatically on first launch. It walks you through provider and endpoint, API key, profile name, live model listing and selection, and per-mode model assignment, then shows a diff review before saving. `rc setup --non-interactive` does the same from flags.
- Named API keys in `~/.config/ruckcode/credentials.toml` (mode 0600), referenced by `api_key_name`, so different projects can use different keys without committing secrets. Manage them with `rc keys list|add|remove|use`.
- `/model` switches models mid-session.

## CLI

- `rc`: TUI with streaming output, collapsible reasoning, tool cards with diffs, a plan panel, permission and question dialogs, token usage, slash commands and Esc to interrupt.
- `rc -p`: headless mode with `--output-format text|stream-json` and `--allow` / `--yolo`. It accepts piped stdin and has exit codes 0 / 1 / 130.
- `rc init`, `rc setup`, `rc keys`, `rc mcp list`, `rc sessions`, `rc acp`.
- A built-in mock model (`provider = "mock"`, then `mock:ask`, `mock:write`, …) for trying the TUI and flows without an API key.

## Install

Download the archive for your platform below, check it against `SHA256SUMS`, and put `rc` on your `PATH`. To build from source, run `cargo install --path crates/ruckcode-cli`.

Builds: Linux x86_64 (glibc and static musl), Linux ARM64, macOS Apple Silicon and Intel, Windows x86_64.
